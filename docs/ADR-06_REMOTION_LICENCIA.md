# ADR-06 — Remotion: license gate and integration design (Step 7c)

Status: approved by the developer for checkpoint A of Step 7c (2026-10-21). Updated 2026-10-22: NovaCiel's Remotion account is on the free plan. Spec sections: 9.4 (editing, subtitles, safe zones), 8 (on-screen text), and the mentions of "plantilla".

## 1. Situation (as of 2026-10-21)
- Spec 9.4 names Remotion as **"the candidate"** for animated text, subtitles and brand templates, and tells us to VERIFICAR its license. It is not a requirement.
- NovaCiel is **3 people** as of 2026-10-21.
- **NovaCiel's Remotion account is on the free plan (confirmed by the developer on 2026-10-22).** The value to use is `REMOTION_LICENCIA=gratuita`. **No `licenseKey` is used and nothing is sent to Remotion**; the "no network while rendering" rule stays.
- **The developer is a freelance contractor working for NovaCiel.** Whether a contractor counts as a person (or an employee) of the organization decides between **3 and 4 people**, and with it between the free license and the company license. This is **open for NovaCiel to answer before production use**. Until then, the free plan rests on that assumption (`SUPUESTO_LICENCIA` in `src/modules/produccion/remotionLicencia.ts`).

## 2. Terms checked
On 2026-10-07 (official site) and again on 2026-10-21 (remotion.pro/license, the `LICENSE.md` of the repository, the docs):
- **Free license:** individuals, non-profits and people evaluating; and, for for-profit organizations, small teams. The website says "up to 3 people"; the repository's `LICENSE.md` says "a for-profit organization **with up to 3 employees**". Commercial use allowed, all features. No sign-up needed.
- **Company license:** required from 4 people (website) or when the organization is not in the free group (`LICENSE.md`); "pay according to usage". Remotion for Automators: **USD 0.01 per render, USD 100 monthly minimum**. Remotion for Creators: USD 25 per seat per month. Enterprise: from USD 500 per month. **Confirm prices before budgeting.**
- `LICENSE.md` says the license **is changing in Remotion 5.0**. The telemetry page says that from 5.0 telemetry through `licenseKey` becomes mandatory for Automators. Therefore we **pin the 4.0.x line** and do not move to 5.x without re-reading the license.
- The license forbids copying or modifying Remotion to sell, rent, sublicense or relicense it. It does not say whether running it on our server to make videos for our clients is covered. We do not resell Remotion; this is a point to confirm before selling the system to other companies.
- Telemetry: the server-side render API sends something (the license key, the IP, video or still) **only when the `licenseKey` option is set**, and only for successful renders. On the free plan we pass **no** `licenseKey` (decision of 2026-10-22), so nothing is sent to Remotion. Telemetry never fails a render.
- All three packages we need (`remotion`, `@remotion/renderer`, `@remotion/bundler`) declare `"SEE LICENSE IN LICENSE.md"`, not an SPDX id. At checkpoint C the `LICENSE.md` of each installed package is read and quoted here.

## 3. The license gate (decision)
- Config: `REMOTION_LICENCIA` = `gratuita` | `empresa`, **no default**, documented in `.env.example`. An empty value counts as unset. The code does not validate the license; it records the operator's declaration.
- **Unset ⇒ Remotion is disabled.** No template is picked, no Remotion code path runs, and the reel is made with the plain text overlays of Step 7b (the production records no template). Any Remotion code path called directly while unset throws `RemotionLicenciaNoConfiguradaError`.
- **Set + a template picked ⇒ any failure fails the piece** with a typed error (Remotion or its browser unavailable, render error, timeout). There is no silent downgrade of a template that was chosen. 7b's rollback and file cleanup apply.
- Remotion sits behind the `CapaTextoAnimado` port (`src/modules/produccion/capaTexto.ts`); the Remotion renderer (checkpoint C) is one adapter, so it can be replaced.

## 4. Review triggers
Review this ADR when any of these happens: a **fourth person** joins NovaCiel (or the contractor question is answered as "counts"); the system is **sold or licensed to other companies** (then also confirm whether running Remotion on our server for clients' videos is covered); we want to upgrade **past 4.0.x**.

## 5. What must happen if the situation changes
- A 4th person, or an answer that the contractor counts: buy the company license **before** the next production use; then set `REMOTION_LICENCIA=empresa`. Under Remotion for Automators, `licenseKey` and telemetry are required from 5.0; they send the machine's IP and break the "no network while rendering" rule, so that needs its own decision (budget per render, an agreement with Remotion on reporting, or a different engine).
- If the license cannot be obtained or paid: **unset `REMOTION_LICENCIA`**. Reels go back to the 7b PNG overlays and nothing else changes. Or replace the adapter.
- **Alternatives:** FFmpeg with canvas (what 7a and 7b already do for text; no animation by word); Revideo.

## 6. Integration design (checkpoint A)
- **Remotion renders only a transparent text layer per scene; the 7b FFmpeg pipeline overlays it, encodes, strips the metadata and verifies.** The verified pipeline and its metadata guarantees stay unchanged, and the client's video never passes through the browser.
- **Alpha format: a PNG sequence** (`capa-00000.png`, …), not ProRes 4444 (roughly 40 MB per second at 1080×1920×30 fps) and not WebM VP9 (FFmpeg's native VP9 decoder drops the alpha channel; it needs `libvpx-vp9` as decoder). A text frame is mostly transparent; the MEASURED size at checkpoint C is 80 to 120 KB per frame (see section 7), 17 to 26 MB for a 7-second scene, in the per-job temp folder removed at the end.
- **Mapping to the timeline:** `durationInFrames` of a composition is exactly `frames` of the scene in the 7b timeline (30 fps). In the FFmpeg arguments, a scene's overlay input changes from a looped PNG to `-framerate 30 -start_number 0 -i file:<dir>/capa-%05d.png`; the pattern is built from a fixed name and an absolute folder, with no client text.
- **Rendering** uses Remotion's Node API (`renderFrames`, `imageFormat: 'png'`), never the CLI, so client text is only an `inputProps` JSON object rendered as React text.
- **Versions:** `remotion`, `@remotion/renderer`, `@remotion/bundler` on the same exact 4.0.x (4.0.537 on 2026-10-21; the latest 4.0.x is pinned at checkpoint C), plus `react` and `react-dom`, pinned, and `@types/react`. No `@remotion/cli`. At C we verify that the pinned Remotion supports the pinned React version and say so in the report.
- **Browser:** Remotion's pinned Chrome Headless Shell, downloaded once into `node_modules/.remotion/chrome-headless-shell/<platform>/` by a setup command (`npm run remotion:browser`), never at render time; the renderer passes `browserExecutable` explicitly. Network off: enforced and proven at checkpoint C, see section 7.
- **Templates** (`src/modules/produccion/plantillas.ts`): `barra_inferior` v1 (the 7a look, animated in), `palabra_a_palabra` v1, `titulo_y_palabras` v1 (title card for the first scene). Colors from `kit_visual` through the 7a contrast rule, fonts only from `assets/fonts`, safe zone from 7a. **Code picks the template** (the client's `kit_visual.plantilla_subtitulos` when it names a registry id; otherwise by the piece's `trabajo`: `atraer` → `titulo_y_palabras`, `confianza` → `barra_inferior`, `accion` → `palabra_a_palabra`); the brief does not, so Step 6 does not change. Spec 9.4 describes 3 or 4 templates *per client* built by NovaCiel: that stays known debt.
- **Word timing** is computed, not transcribed (reels have no voice yet): words weighted by their length over the speaking window of the scene, with a lead-in of 150 ms, a final hold of at least 500 ms, a minimum of 180 ms per word, and the last word held to the end. The same `{ palabra, inicioMs, finMs }` shape will come from the voice provider in 7d.
- **Schema:** `producciones.plantilla` and `plantilla_version` (migration 2000), both set or both null; null for images and for reels made with the PNG overlays. The np1 hash does not change.

## 7. Checkpoint C: what was built and measured (2026-10-22)
**Versions (exact, installed):** `remotion`, `@remotion/renderer`, `@remotion/bundler` **4.0.537** (all the same); `react` and `react-dom` **19.3.1** (MIT); dev: `@types/react` 19.3.0 and `@types/react-dom` 19.3.0. `@remotion/cli` and `@remotion/google-fonts` are NOT installed. `npm audit`: 0 vulnerabilities in the whole tree (351 packages after the install, 165 added). Disk: `node_modules` went from 221 MB to 455 MB (+234 MB) and the downloaded Chrome Headless Shell (157.0.8080.0, win64) adds 283 MB in `node_modules/.remotion`.

**React compatibility.** The three Remotion packages declare `peerDependencies` `react` and `react-dom` `>=16.8.0`, which includes 19.3.1; and what matters: **the real renders of the render tests ran correctly with React 19.3.1 and Remotion 4.0.537** (all templates, word timing and transparency checks pass).

**Licenses read from the installed packages.** The `LICENSE.md` of `remotion`, `@remotion/renderer` and `@remotion/bundler` are identical. Free License, eligibility: "an individual; a for-profit organization with up to 3 employees; a non-profit or not-for-profit organization; evaluating whether Remotion is a good fit, and are not yet using it in a commercial way". Allowed: "to use the software non-commercially or commercially for the purpose of creating videos and images and to modify the software". Not allowed: "to copy or modify Remotion code for the purpose of selling, renting, licensing, relicensing, or sublicensing your own derivate of Remotion". The file also says: "In Remotion 5.0, the license will slightly change." The Chrome Headless Shell is Google's Chrome for Testing build (BSD-style and third-party licenses inside its folder), downloaded by Remotion's own tooling.

**Spike results (before building).** (1) Request interception: **NO**. Remotion's browser is its own fork: `target.page()` fails (`sourceMapGetter`) and pages have no `setRequestInterception`. (2) Frame names: `capa-[frame].png` gives `capa-0.png`, `capa-1.png`... without padding for a 10-frame render; the adapter parses the number and renames to `capa-00000.png` whatever the padding is. (3) The frames are 8-bit RGBA PNGs (color type 6). (4) `browserExecutable` makes Remotion use that browser without downloading anything. (5) React 19.3.1 rendered correctly. (6) A first bundle takes about 31 s; the disk-cached bundle (34 MB) is reused afterwards.

**Network off: how it is enforced and proven.** Interception is not available, so the enforcement is **a Content-Security-Policy written into the bundle's `index.html` after bundling** (`POLITICA_CSP` in `remotionBundle.ts`): the page may load only its own origin, `data:` and `blob:`, for scripts, styles, images, fonts and `fetch`; frames, objects and forms are denied. A request to anywhere else is **blocked by the browser before it leaves**, and reported as a console message ("violates the following Content Security Policy directive"), which the adapter turns into `CapaTextoError('solicitud_externa')` and removes the frames. Proven with a reachable local server that counts hits: a fixture composition that tries a `fetch` and an `<img>` to it gets **0 hits with the policy and 2 hits without it** (the CONTROL test, which builds the same fixture straight with Remotion). The bundle is never reused if its `index.html` lacks the policy, and the policy is part of the cache key. No `licenseKey` is passed (nothing is sent to Remotion), fonts come from the bundle (`staticFile()`), `disableWebSecurity` stays false, and the browser is never downloaded during a render.

**Measured on this laptop (Windows, 1080×1920, 30 fps, 210-frame = 7 s scene, 4 tabs):** Per-template numbers from the smoke run: `barra_inferior` 100.3 KB per frame (21.6 MB in total), `palabra_a_palabra` 80.8 KB (17.4 MB), `titulo_y_palabras` 120.3 KB (25.9 MB); render time about **12 s for the 210 frames (about 59 ms per frame)**, plus the bundle the first time (about 31 s, then cached on disk). The PNG sequence of a reel of 5 scenes is therefore around 100 MB of temporary files, removed after the reel is produced. The estimate of section 6 (10 to 60 KB) was too low.

**What the deployment needs.** The server must ship `remotion/` and `assets/fonts` (the bundle is built from source at runtime, not from `dist/`), run `npm run remotion:browser` once (it needs the network that one time) and, on Linux, install the system libraries Chrome Headless Shell needs (Remotion's "Linux dependencies" list). `REMOTION_NAVEGADOR` can point to another copy of the browser.

**Known debt from C.** Frames after the last word appears are identical (they could be hard-linked instead of stored); one browser is opened per scene (it could be shared across the scenes of a reel); old cached bundles in `.data/remotion` are not cleaned up yet.
