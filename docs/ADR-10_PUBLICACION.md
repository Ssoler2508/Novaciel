# ADR-10: Publishing

Status: built (Step 10, checkpoints A to E), with the **real adapter pending** (checkpoint F, written only after NovaCiel chooses the intermediary and puts its key in `.env`).

## Context
The central rule of the system is that nothing is sent to a social network unless the exact current production was approved by a person at both levels. Step 9 built the gate (`assertPublicable`). Step 10 builds everything around the send, behind a port with a fake, so the whole flow is tested without a network and the choice of intermediary does not change the design.

## Decisions

1. **A port, `PublishProvider`** (`src/lib/publish/`), with `FakePublishProvider` now and the real adapter in checkpoint F. It receives the network, the ordered files (local paths, already re-hashed), the stored caption, hashtags, alt texts and location, the AI-content flag and the idempotency key; it returns an external id and a permalink. Other operations: `findByKey`, `getMetrics`, `normalizarMetricas`, `soportaEtiquetaIa`. The credentials arrive in a per-call context, decrypted at that moment, never in the constructor, never logged. Config: `PUBLISH_PROVIDER=fake` (default outside production; unset in production is a startup error, like the language model and the voice).
2. **Two connection models are supported by the same port**: an intermediary with one account key in `.env` plus a per-client profile key stored encrypted in `conexiones_redes`, or direct network APIs with OAuth bundles per client in `conexiones_redes` (the adapter refreshes). `conexiones_redes` only gained a `UNIQUE (id, cliente_id)` so the attempts can bind to it with a composite foreign key.
3. **States**: no new ones. `aprobada → programada → publicada → en_medicion → cerrada`; a definitive failure is `programada → fallo_publicacion` (spec 15) with a critical alert, and `fallo_publicacion → programada` is the manual retry, which goes through the very same rules as the first schedule (`programarPieza`). An unknown outcome leaves the piece in `programada` with the attempt marked `desconocida`. Cancelling a schedule is `programada → con_cambios`.
4. **Records** (migration `1700000002600`, all append-only): `publicaciones` (one row per attempt, written and committed BEFORE the network call), `publicaciones_resultados` (`publicada`, `fallida` or `desconocida`; only a `desconocida` can be followed by a second result that settles it) and `metricas_pieza` (one snapshot per publication and window). No provider message is stored, only a closed error category. The database makes a double publication impossible: consecutive attempt numbers, a new attempt only after the previous one ended `fallida`, one `publicada` result per production and per piece, and an attempt bound to the exact current production (version, `hash_version`, `hash_pieza`), a `programada` piece and an active connection.
5. **Idempotency**: the key is `pi1:<sha256>` of a canonical serialization of the piece, the production and its np1 hash; it is the same for every attempt of a production. A retry first asks the provider by key; an attempt without a result younger than 10 minutes is "in flight" (`en_curso`, no provider call); an older one is treated as crashed and is looked up by key. A lookup that finds nothing settles the attempt as failed and a new attempt may follow only while the 3 attempts are not used up; used up with no known outcome it stays `desconocida` with an alert and is never resent. Verification lookups therefore count toward the maximum.
6. **No transaction is open during a network call.** Phase 1 (transaction): lock plan then piece, the piece is `programada` and its time has come, `assertPublicable` passes, the attempt is recorded, commit. Phase 2 (no transaction): decrypt the credentials now, look up by key if this is a retry, read the stored files back, re-hash them against the recorded SHA-256 and send. A file that changed between the gate and the send is not sent: the attempt is closed as failed and the piece goes to `fallo_publicacion`. Phase 3 (transaction): lock again, record the result and move the piece; if the production changed meanwhile, the result is still recorded (the post is out) and a critical alert is raised.
7. **AI-content label**: `etiqueta_ia` is read from the quality-control report bound to the current production hash (`voz_etiqueta_ia_pendiente`). If the provider or the network cannot set it, the send is blocked (`etiqueta_ia_no_soportada`, piece to `fallo_publicacion`) until NovaCiel decides.
8. **Retries** (all values VERIFY): 3 attempts in total; rate limit, server and timeout are retried with a growing, jittered, bounded wait (30 s × 4ⁿ, ±20 %, at most 10 min; a provider `Retry-After` is respected); auth, quota and bad request are not retried and alert. Each retry is a new queue job with its own key, so pg-boss itself never retries.
9. **Scheduling**: permission `schedule_pieces` (administrador, operador; NovaCiel only). The time must be in the future and outside the vetoed hours of the plan's zone. `fecha_hora` is not part of np1, so a reschedule keeps the approvals; it queues the reminders and the `vencimiento` notice again (the old jobs carry the old deadline and do nothing).
10. **No approval at the scheduled time (spec 11.3)**: a piece still in `revision_novaciel` or `esperando_aprobacion` when its time comes is never published. The minute sweep moves it to the next allowed 15-minute slot at least 24 absolute hours ahead (VERIFY), queues the notices again and raises `publicacion_sin_aprobacion`. After 3 automatic reschedules in a row it stops and raises the critical `publicacion_reprogramaciones_agotadas`.
11. **Jobs** (pg-boss, every worker wrapped with `withFailureAlert`; every job re-checks the state when it fires and is a no-op if the piece, its production or its time changed): `publicacion-publicar` (singleton per piece, production, time and round), `publicacion-barrido` (every minute: the rule above, plus a safety net that queues the send again when a scheduled or retry job never ran) and `publicacion-metricas` (every 15 minutes).
12. **Metrics**: snapshots at 24 h, 72 h, 7 d and 28 d after publishing (spec 12.1; VERIFY); a metric the network does not report is NULL, never 0, and so are the sums over pieces that do not report it. The first snapshot moves the piece to `en_medicion` and the 28-day one to `cerrada`.
13. **Alerts added to the ADR-09 catalogue**: `publicacion_fallida`, `publicacion_resultado_desconocido`, `publicacion_sin_aprobacion`, `publicacion_reprogramaciones_agotadas`, `conexion_red_vencida`, `etiqueta_ia_no_soportada`.
14. **Cost**: publishing does not go through the budget while the intermediary is a subscription. If it charges per post, a price unit `publicaciones` is added in checkpoint F; the fake needs no price.

## Known debt
